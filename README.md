# Body tracker

Трекер тренировок: отметки «йога» и «зал» по дням, недельный план как данные,
работа офлайн с досылкой при появлении сети.

Один бэкенд, три клиента:

| | Фронт | Данные |
|---|---|---|
| Браузер | с Vercel | Vercel API |
| macOS | бандл внутри `.app` | Vercel API |
| iOS | бандл Expo | Vercel API |

## Структура

```
api/            FastAPI + SQLAlchemy async + Alembic → Postgres
packages/
  core/         типы · API-клиент · даты · движок синхронизации
  plan/         plan.json · схема · селекторы
apps/
  web/          React + Vite
  mobile/       Expo
  menubar/      Swift, приложение в строке меню
```

Питон в воркспейсы pnpm не входит — у него свой `pyproject.toml` и `uv`.

## Как ходят данные

Нажатие пишется в локальный кэш сразу и кладётся в очередь со временем клиента.
Очередь уезжает на сервер, когда есть сеть. Чтение — не диапазонами, а дельтой:
клиент хранит курсор `rev` и просит всё, что больше.

Две колонки с разными задачами:

| | Кто ставит | Зачем |
|---|---|---|
| `rev` | сервер, монотонно | курсор дельта-синхронизации |
| `updated_at` | клиент | разрешение конфликта, побеждает большее |

Строка на день и два булевых поля сходятся сами, поэтому last-write-wins здесь
не компромисс, а корректное решение.
